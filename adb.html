Auto-proxy и разрешение ADB

Как выдать приложению одноразовое разрешение, чтобы системный прокси включался и выключался автоматически.

English version ↓

Зачем это нужно

Auto-proxy выставляет глобальный HTTP-прокси Android при подключении и снимает его при отключении. Менять этот параметр обычному приложению нельзя: нужно разрешение WRITE_SECURE_SETTINGS, которое не выдаётся из настроек. Его выдают один раз через ADB с компьютера.

  • Root не нужен.
  • Разрешение сохраняется после перезагрузки и обновлений приложения.
  • Сбрасывается после удаления приложения — тогда его нужно выдать снова.
  • Без разрешения работают TUN-режим (Full) и ручная настройка прокси в Wi-Fi.

Что понадобится

  • Компьютер с Windows, macOS или Linux — или Shizuku на самом телефоне (Android 11+).
  • Кабель USB и отладка по USB — или беспроводная отладка для Shizuku.
  • adb из Android Platform Tools — или Shizuku и Termux, если обходитесь без компьютера.

Шаг 1. Включите отладку по USB

  1. Настройки → О телефоне → нажмите «Номер сборки» 7 раз. Появится пункт «Для разработчиков».
  2. Настройки → Система → Для разработчиков → включите «Отладка по USB».
На MIUI и HyperOS дополнительно включите «Отладка по USB (Настройки безопасности)» в меню для разработчиков. Без этого pm grant может вернуть not allowed.

Шаг 2. Подключите телефон

Подключите телефон кабелем и проверьте, что компьютер его видит:

adb devices

В списке должно появиться устройство со статусом device. Если статус unauthorized, разблокируйте телефон и подтвердите запрос «Разрешить отладку по USB».

Шаг 3. Выдайте разрешение

Full (cc.iinv.app):

adb shell pm grant cc.iinv.app android.permission.WRITE_SECURE_SETTINGS

Lite (cc.iinv.app.lite):

adb shell pm grant cc.iinv.app.lite android.permission.WRITE_SECURE_SETTINGS

Команда ничего не выводит, если всё прошло успешно. Проверить можно в приложении: «Обслуживание» → «Прокси» → значок обновления (↺).

Правила для приложений

Чтобы IINV переключал прокси для отдельных приложений (App Monitor), нужен доступ к статистике использования. Он есть только в Full-сборке: 

adb shell appops set cc.iinv.app android:get_usage_stats allow

Этот же доступ можно включить без ADB: Настройки → Приложения → Специальный доступ → Доступ к данным об использовании → IINV.

Шаг 4. Проверьте

Подключитесь в IINV и посмотрите на главный экран: должно быть «Системный прокси: активен». Или выполните на компьютере: 

adb shell settings get global http_proxy

Пока соединение активно, значение будет вида 127.0.0.1:10808 (порт зависит от профиля). После отключения — :0 или null.

Без компьютера: Shizuku

Если нет кабеля и ПК, разрешение можно выдать через Shizuku — приложение, которое запускает shell-сервис с правами ADB. Нужен Android 11+ и Wi-Fi, root не требуется.

В IINV 3.2.0 проще: откройте мастер разрешений (баннер на главной или «Сеть» → «Дать разрешение»), выберите Shizuku и следуйте подсказкам. Приложение само запустит Shizuku-сервис и выдаст разрешение — Termux и rish не нужны. Инструкция ниже — если мастер не сработал.
  1. Установите Shizuku из Google Play или с GitHub.
  2. Включите «Для разработчиков» → «Отладка по Wi-Fi».
  3. Откройте Shizuku → «Запустить» → «Сопряжение». Затем в «Отладке по Wi-Fi» нажмите «Подключение по коду» и введите код в уведомление Shizuku.
  4. Установите Termux. В Shizuku откройте «Использовать Shizuku в терминале» и выберите каталог Termux.
  5. В Termux запустите rish и выполните команды без adb shell: 
rish
pm grant cc.iinv.app android.permission.WRITE_SECURE_SETTINGS
appops set cc.iinv.app android:get_usage_stats allow
exit

Для Lite замените пакет на cc.iinv.app.lite. Если команда rish не найдена, запустите ~/rish.

Shizuku нужен только на время выдачи разрешения. После этого его можно остановить или удалить — разрешение IINV сохранится. После перезагрузки Shizuku запускается заново (на Android 11+ снова через отладку по Wi-Fi), но выданное разрешение не сбрасывается.

На Android 10 и старше без root Shizuku запускается только с компьютера: беспроводная отладка появилась в Android 11. На рутированном устройстве можно выбрать запуск через root. На MIUI/HyperOS для Shizuku также включите «Отладка по USB (Настройки безопасности)».

Беспроводная отладка с компьютером

Если компьютер есть, а кабеля нет, на Android 11 и новее можно подключиться по Wi-Fi: «Для разработчиков» → «Отладка по Wi-Fi» → «Подключение по коду». Сопряжение: 

adb pair 192.168.1.10:41234
adb connect 192.168.1.10:5555

Адрес и порт показаны на телефоне. Дальше команды те же.

Как отозвать разрешение

adb shell pm revoke cc.iinv.app android.permission.WRITE_SECURE_SETTINGS
adb shell appops set cc.iinv.app android:get_usage_stats deny

Для Lite замените пакет на cc.iinv.app.lite. Удаление приложения также сбрасывает разрешения.

Если не получается

  • no devices/emulators found — проверьте кабель, режим USB (передача файлов) и драйверы; на Linux могут понадобиться udev-правила.
  • unauthorized — разблокируйте телефон и подтвердите отпечаток компьютера.
  • not allowed — включите «Отладка по USB (Настройки безопасности)» на MIUI/HyperOS.
  • Unknown package — проверьте имя пакета (Full или Lite) и что приложение установлено в текущем профиле.
  • Разрешение выдано, но автопрокси не работает — нажмите ↺ в настройках прокси, переподключитесь и проверьте, что не включён другой прокси или VPN.
Коротко: с компьютером — включите отладку по USB и выполните adb shell pm grant <пакет> android.permission.WRITE_SECURE_SETTINGS; без компьютера — те же команды в rish через Shizuku. Затем нажмите ↺ в настройках прокси. Для App Monitor добавьте appops set <пакет> android:get_usage_stats allow.

English ↑ Русский

How to grant the one-time permission that lets IINV enable and disable the system proxy automatically.

Why this is needed

Auto-proxy sets Android's global HTTP proxy when a connection starts and clears it when the connection stops. Regular apps cannot change this setting: it requires WRITE_SECURE_SETTINGS, which cannot be granted from the Android UI. Grant it once over ADB from a computer.

  • No root required.
  • The grant survives reboots and app updates.
  • Uninstalling the app resets it; grant it again after reinstalling.
  • Without the grant, TUN mode (Full) and the manual Wi-Fi proxy still work.

Requirements

  • A computer running Windows, macOS or Linux — or Shizuku on the phone (Android 11+).
  • A USB cable with USB debugging enabled — or wireless debugging for Shizuku.
  • adb from Android Platform Tools — or Shizuku and Termux if you have no computer.

Step 1. Enable USB debugging

  1. Settings → About phone → tap "Build number" seven times to unlock Developer options.
  2. Settings → System → Developer options → enable "USB debugging".
On MIUI and HyperOS also enable "USB debugging (Security settings)" in Developer options. Without it pm grant may return not allowed.

Step 2. Connect the phone

Connect the phone and check that the computer sees it:

adb devices

You should see the device with the device status. If it says unauthorized, unlock the phone and confirm the "Allow USB debugging" prompt.

Step 3. Grant the permission

Full (cc.iinv.app):

adb shell pm grant cc.iinv.app android.permission.WRITE_SECURE_SETTINGS

Lite (cc.iinv.app.lite):

adb shell pm grant cc.iinv.app.lite android.permission.WRITE_SECURE_SETTINGS

The command prints nothing on success. Check in the app: Maintenance → Proxy → refresh (↺).

Per-app rules

To let IINV switch the proxy per app (App Monitor), grant usage access. It is available in the Full build only: 

adb shell appops set cc.iinv.app android:get_usage_stats allow

You can also enable it without ADB: Settings → Apps → Special app access → Usage access → IINV.

Step 4. Verify

Connect in IINV and check the home screen: it should say "System proxy: active". Or run: 

adb shell settings get global http_proxy

While connected the value looks like 127.0.0.1:10808 (the port depends on the profile). After disconnecting it is :0 or null.

Without a computer: Shizuku

If you have no cable or PC, grant the permission through Shizuku — an app that runs a shell service with ADB privileges. It requires Android 11+ and Wi-Fi; no root.

IINV 3.2.0 makes this easier: open the permission wizard (the home banner or Network → Grant access), choose Shizuku and follow the prompts. IINV starts the Shizuku service and grants the permission itself; Termux and rish are not needed. The steps below are a manual fallback.
  1. Install Shizuku from Google Play or GitHub.
  2. Enable Developer options → Wireless debugging.
  3. Open Shizuku → Start → Pairing. Then tap "Pair device with pairing code" in Wireless debugging and enter the code in Shizuku's notification.
  4. Install Termux. In Shizuku open "Use Shizuku in terminal apps" and select the Termux directory.
  5. In Termux run rish and execute the commands without adb shell: 
rish
pm grant cc.iinv.app android.permission.WRITE_SECURE_SETTINGS
appops set cc.iinv.app android:get_usage_stats allow
exit

For Lite replace the package with cc.iinv.app.lite. If rish is not found, run ~/rish.

Shizuku is only needed while granting. You can stop or uninstall it afterwards; IINV keeps the permission. After a reboot Shizuku has to be started again (wireless debugging on Android 11+), but the grant stays.

On Android 10 and older, Shizuku without root can only be started from a computer: wireless debugging arrived in Android 11. On a rooted device you can start it through root. On MIUI/HyperOS enable "USB debugging (Security settings)" for Shizuku as well.

Wireless debugging with a computer

If you have a computer but no cable, Android 11+ can connect over Wi-Fi: Developer options → Wireless debugging → Pair device with pairing code. 

adb pair 192.168.1.10:41234
adb connect 192.168.1.10:5555

The address and port are shown on the phone. The rest of the commands are the same.

Revoking the permission

adb shell pm revoke cc.iinv.app android.permission.WRITE_SECURE_SETTINGS
adb shell appops set cc.iinv.app android:get_usage_stats deny

For Lite use cc.iinv.app.lite. Uninstalling the app also resets the permissions.

Troubleshooting

  • no devices/emulators found — check the cable, USB mode (file transfer) and drivers; Linux may need udev rules.
  • unauthorized — unlock the phone and confirm the computer's fingerprint.
  • not allowed — enable "USB debugging (Security settings)" on MIUI/HyperOS.
  • Unknown package — check the package name (Full or Lite) and that the app is installed in the current profile.
  • The permission is granted but auto-proxy does not work — press ↺ in proxy settings, reconnect, and make sure no other proxy or VPN is active.
In short: with a computer, enable USB debugging and run adb shell pm grant <package> android.permission.WRITE_SECURE_SETTINGS; without one, run the same commands in rish via Shizuku. Then press ↺ in proxy settings. For App Monitor add appops set <package> android:get_usage_stats allow.
